# 공개 파일 관리

GitHub Pages에서 사이트를 유지하며 엑셀 원본과 조사 자료를 현재 공개 파일 목록에서 제외합니다. 화면에 표시하는 정보의 복제를 완전히 막는 기능은 아닙니다.

## 로컬에만 보관하는 자료

- `업체정보/업체정보_간편입력.xlsx`와 다른 Excel 원본
- `data/venues.json`: 엑셀 행 번호·파일명과 조사 근거를 포함한 전체 원본
- `data/`의 주소 좌표 캐시, 과거 조사 목록과 가져오기 기록

위 자료는 Git 추적에서만 제외하고 컴퓨터에는 보존합니다. `.gitignore`에 엑셀 확장자와 `/data/`를 등록했습니다. 원본은 운영자가 별도 비공개 위치에 백업해야 합니다. 저장소를 새로 복제해도 원본은 복원되지 않습니다. 다른 컴퓨터에서 엑셀을 수정하려면 운영자 백업에서 원래 경로로 복원하세요.

## 업데이트 순서

```powershell
python scripts/import-workbook.py
node scripts/apply-registered-coordinates.cjs
npm run build
npm test
npm run test:local
```

로컬 빌드는 `data/venues.json`에서 필요한 필드만 골라 `public/data.js`를 생성합니다. 엑셀 행 번호·원본 파일명·좌표 조사 내부 필드와 임의의 새 관리 필드는 공개 데이터에 포함하지 않습니다. 동반 조건 메모는 방문자에게 보이는 정보이므로 개인 연락처나 비공개 운영 메모를 입력하지 마세요.

GitHub Actions 또는 원본 없이 복제한 환경은 `public/data.js`로 빌드하고 공개 기능 검사를 실행합니다. `npm run test:local`은 로컬 원본·엑셀·좌표 캐시가 필요한 별도 검사입니다. 원본이 손상됐다면 공개 데이터로 조용히 대체하지 않고 실패합니다.

엑셀 수정 후에는 로컬에서 빌드한 공개 파일을 커밋해야 사이트가 갱신됩니다. GitHub Actions는 공개되지 않은 로컬 엑셀 변경을 알 수 없습니다.

## 배포 검사

빌드는 허용된 HTML/CSS/JavaScript와 `assets/` 아래 이미지 파일만 배포합니다. 원본 JSON, 엑셀, 백업이나 심볼릭 링크가 `public/`에 들어오면 실패합니다. 공개 검사에서는 Git 추적 목록에 `data/` 또는 Excel 파일이 다시 들어가지 않는지도 확인합니다.

위치 자동 검색, 주소·장소 검색, 전국 업체명 검색, 지도와 필터에 필요한 이름·주소·좌표·이용 조건은 유지합니다.

## 보호 범위와 과거 기록

`public/data.js`에는 사이트에서 사용하는 전체 업체 표시 정보가 들어 있어 방문자가 내려받을 수 있습니다. 이 변경은 엑셀 원본과 내부 자료의 불필요한 공개를 줄이는 조치이며, 공개 업체 목록 전체의 수집 방지는 아닙니다.

2026-11-13에 전체 Git 기록을 로컬에 백업한 뒤 공개 브랜치 기록을 재작성했습니다. 과거 기록에서도 Excel 파일과 `data/` 원본·조사 자료를 제외하고 과거 브라우저 데이터와 테스트 데이터의 내부 필드를 공개용 필드로 정리했습니다. 현재 업체 표시 데이터와 검색 기능은 유지합니다.

기록 재작성 전 저장소를 복제한 다른 컴퓨터에서는 기존 기록을 다시 푸시하지 마세요. 필요한 로컬 변경과 비공개 원본을 따로 백업한 뒤 새로 복제하는 방법을 권장합니다. 엑셀과 `data/`는 새 복제본에 포함되지 않으므로 비공개 백업에서 복원해야 합니다.

이 작업은 공개 브랜치에서 따라갈 수 있는 기록을 정리합니다. GitHub에 남은 예전 커밋 직접 링크·캐시와 기존 다운로드 사본까지 삭제됐다는 보장은 아닙니다. 서버에 남은 사본의 제거는 GitHub 측 처리가 필요할 수 있습니다. 로컬 복구용 백업에는 정리 전 원본이 있으므로 외부에 업로드하거나 공유하지 마세요.
